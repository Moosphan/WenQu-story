# 全局创作助手

选择作品后，页面右上角的「创作助手」可在项目概览、写作、规划、资料库和审校页面打开。对话按作品保存在本地；关闭窗口不取消已发送的请求，刷新后可继续查看。

可以讨论世界观、人物动机、卷纲、章纲或具体段落。在写作页选择章节并勾选「附带正文」后，助手会得到该章已保存的定稿或候选稿；未保存的编辑不会发送。上下文包含完整故事约定和卷纲、覆盖全书的压缩章节路线图、最近六轮压缩对话、最新提案，以及选中章节的有界正文。未载入的历史正文不能被当作已核实事实。

普通回答只提供建议。需要调整整体规划时，助手可生成「待确认」方案，展示规划方向和拟更新的故事约定。作者可以继续讨论；后续对话会使旧方案失去直接应用资格。作品版本变化也会阻止旧方案应用。

点击「确认方案并重排后续章纲」后启动独立规划：保留已有正文、候选稿及对应章节骨架，分批重排后续章纲，并校验卷纲连续覆盖全书。首批输出协议要求完整卷纲；后续省略时沿用本轮已验证的卷纲，明确返回空卷纲或不完整卷纲仍会拒绝。全部完成后才一起发布新故事约定和章纲。取消规划保留原配置；规划完成后暂停，章节生成由作者单独启动。普通对话不会直接修改正文或人物资料。

页面顶部与写作侧栏同时显示已保存章数、当前批次及暂停原因，侧栏提供继续／取消规划。进度按批次校验成功后更新，模型生成期间不会伪造逐字或逐章进度。

示例问题：

> 这本书计划 200 章，但目前的世界格局一直局限在同一宗门。请分析卷纲和章纲中的问题，提出更宏大的修仙叙事方案。说明各卷如何扩大地域与势力范围、主角能力与责任如何成长，以及已有亲情线、人物和伏笔如何承接。避免只换地图或机械抬高境界。保留现有正文，先给我可讨论的方案。

SQLite 版本为 12，新增 `author_assistant_turns`。服务重启会把未完成的助手请求标为可重发的失败状态，避免永远显示思考中。配置与调用失败不会写入原始凭据或提供商异常信息。

验证：601 项测试通过；独立假模型浏览器验证了多轮讨论、刷新恢复、显式确认重排和完成后暂停。真实 200 章作品经已配置 Codex 执行器返回了讨论回复与待确认提案，页面可继续讨论或确认；核对确认作品版本、正式配置、故事约定、章纲、正文及候选稿均未改变。真实作品方案需由作者审阅后确认，测试通过不代表文学设计已符合作者偏好。
